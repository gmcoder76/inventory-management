Filter Data Flow

End-to-end path when a user selects a filter — e.g. "London" warehouse + "Sensors" category

1 — User Interaction
User selects filter in FilterBar.vue selectedLocation = "London" selectedCategory = "sensors" Stored in useFilters() composable singleton — reactive across all views
→
2 — View Reacts
Each view watch()es filter refs and calls its load function const filters = getCurrentFilters() // { warehouse: "London", // category: "sensors" }
→
3 — API Call
api.js builds query string via URLSearchParams GET /api/inventory ?warehouse=London &category=sensors
→
4 — Backend Filters
apply_filters() in main.py filters in-memory list filtered = [i for i in items if i['warehouse'] == warehouse and i['category'].lower() == category.lower()]
→
5 — Pydantic + Response
FastAPI validates each item against Pydantic model, serialises to JSON response_model= List[InventoryItem] Vue updates computed properties and re-renders

Shared State (Composables)

useFilters()
Global filter state — singleton shared across all views and FilterBar
selectedPeriod ref — 'all' | '2025-01' … '2025-12'
selectedLocation ref — 'all' | warehouse name
selectedCategory ref — 'all' | category name
selectedStatus ref — 'all' | status name
hasActiveFilters computed boolean
getCurrentFilters() → API param object
resetFilters() set all to 'all'
useAuth()
Mock authentication — hardcoded user, always authenticated
currentUser computed — name, email, phone, tasks[]
isAuthenticated ref — always true
getInitials() → name initials string
logout() shows alert (demo)
useI18n()
Internationalization — English / Japanese toggle with currency switching
currentLocale ref — 'en' | 'ja'
currentCurrency ref — 'USD' | 'JPY'
t(key) → translated string
